# 项目经验

- 删除确认弹窗这类遮罩 UI，要区分“背景 barrier 允许半透明”和“弹窗卡片 surface 必须不透明”。用户要求“不要黑色背景，只让卡片不透明”时，不能用加深整个背景替代修正卡片 surface。
- 长按删除这类危险操作不能用裸 pointer down 定时器自证成功；应绑定 Flutter 长按手势生命周期，让滚动、取消和手势竞争自然取消进度，避免误触。
- Harmony Flutter 插件注册失败时，不能只清缓存；如果 `.flutter-plugins-dependencies` 缺 `plugins.ohos`，自管 hvigor 插件必须能从 `dependencyGraph` 和 `.dart_tool/package_config.json` 回退识别 `ohos/oh-package.json5`，并且用标准 `fileURLToPath` 还原 `file://` package URI，避免丢失 `/Users/...` 的前导斜杠。
- 双机真机问题不能把单端页面、单端日志或服务端健康检查包装成“测试成功”。必须同时确认两台设备都实际进入目标 App 状态，并用双端日志或 UI 状态互相印证后再下结论。
- 用户明确“两台已打开视频通话页”或“不要再切页面”后，后续验证只能做只读抓取：截图、logcat、服务端日志、包信息。不得再用 `monkey`、`am start`、`input tap` 或安装动作改变设备页面；如确需安装新包，先说明安装会打断页面，安装后等待用户重新打开目标页。

- 双端 RTC 排障时，必须先向用户区分 UI 连接状态和原生 SDK 媒体面入会状态；如果修复异步入会判断会让“已连接”变成“连接失败”，要提前说明这是暴露真实失败而不是媒体链路倒退，并给用户一个是否保留旧展示的选择。
- 审查 GitHub Actions 构建数量时，不能只看 job 显示名里的 matrix 字段组合下结论；必须同时核对 matrix include 数量、artifact 名称和构建命令。`(arm64-v8a, arm64)` 这类显示通常是“产物 ABI + Flutter target 映射”，不等于构建了两个 APK。
- 做 GitHub Actions 自动版本号时，不能只确认解析步骤算出了 `version_build`；必须同时确认 Android / iOS 构建命令都显式消费这个值，例如 `flutter build ... --build-number`，否则可能出现日志显示自动递增但产物版本号仍沿用 `pubspec.yaml` 或平台默认值。
- 用户要求“版本号递增”时，必须分清内部构建号 `+build` 和用户可见外显版本 `beta.N`；Release tag、文件名、Android `versionName`、iOS `CFBundleShortVersionString` 都要一起核对，不能只改内部 build number。
- 设计宠物端常驻监控屏时，不能把主人端的信息密度搬过去；宠物端首要职责是观察与少量状态提示，默认应保留宠物身份、连接状态、当前/下一条关键提醒和设置入口，避免清单、指标和多面板堆叠。
- 宠物端常驻屏和选择接管屏都应避免说明性文案堆叠；已由标题、状态胶囊和可点击卡片表达的含义，不要再补接管后的解释性引导句。横屏窄侧栏里的时间、标题和状态胶囊必须优先防止拆字、越界和强制换行。
- 宠物端监控屏的头像不能占据主体空间；竖屏应让头像/身份区服务于识别，提醒或监控操作区才是主区域，默认按约 3:7 的视觉比例规划。
- 横屏宠物端同样遵循头像+状态与待办约 3:7 的比例；连接状态应附着在头像区域下方，底部或右侧主体空间优先留给待办内容。
- 视频通话的摄像头关闭状态是双向媒体状态，不能只绑定本地按钮 UI；对端关闭摄像头时也要通过信令同步，并让“摄像头已关闭”遮罩跟随远端画面在主画面和小窗之间切换，避免把 RTC 黑帧暴露给用户。
- 视频通话里 RTC 画面是 Android/iOS/Harmony 原生 PlatformView，摄像头关闭态不能只依赖“在原生视图上盖 Flutter 遮罩”；关闭态应直接替换为 Flutter 占位层，避免主副画面切换或平台视图层级变化后黑帧重新露出。
- iOS 宠物头像路径不能只信任历史沙盒绝对路径；App 更新后容器基路径可能变化，加载数据时需要按当前 Application Support 的 `pet_photos` 目录重定位旧头像文件，并把迁移后的可读路径写回本地存储。
- 判断同步稳定性时不能用服务端健康检查、PowerSync 试验分支状态或客户端单元测试替代主线 legacy 服务端同步流测试；涉及 action 重放、剪枝、重启恢复和同一事项新旧操作收敛时，必须跑 `server/test/sync_flow_test.dart`。
- 时间显示“看起来会刷新”不等于真实实时刷新；列表页和详情页这类独立页面如果展示与当前日期/时间相关的文案，必须有页面级定时刷新或订阅源，并用页面保持打开的 widget 测试验证。
- 常驻屏时间刷新不能只覆盖前台静止场景；如果依赖页面级 timer，必须同时处理 App 退后台、锁屏、系统暂停 timer 后恢复前台的生命周期，恢复时立即重取系统时间并重排下一次刷新。
